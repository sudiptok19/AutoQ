# Architecture & Decision Log

Short entries. Newest at the bottom. Format: decision — why — tradeoff.

1. **Modular monolith (FastAPI) + SPA (Vite/React).** Smallest design where policy, CV and crypto share one authoritative process. — Tradeoff: one backend to scale; fine for a hackathon and a pilot.
2. **Vite SPA, not Next.js.** No SSR/SEO need; PWA/offline and one codebase for desktop + phone are simpler. — Tradeoff: no server components.
3. **PostgreSQL over SQLite.** Dispatch gate and recall need row locks (`SELECT … FOR UPDATE`) and unique constraints under concurrency. — Tradeoff: needs Docker.
4. **Per-piece serialized units.** Inspection, passport and packing are per unit so we never claim a bulk lot was individually inspected. Bulk items are out of scope. *Sampled lot release added in #15.*
5. ~~**Passports issued on PASS even during containment.**~~ *Superseded by #14.* Resolves the brief's "no passport until first N pass" vs "mint during containment" contradiction. Eligibility is never stored; the gate recomputes it.
6. **Override ≠ release.** A QE/QM review of a HOLD can only send the unit back for reinspection or reject it. No admin bypass anywhere.
7. **Golden-reference alignment + diff before PatchCore.** Works on a laptop with phone photos and a small image set; reports a raw anomaly score, not a probability. PatchCore is P2.
8. **Ed25519, canonical JSON, `AQ1.` tokens with `kid`.** Widely reviewed, fast, small signatures that fit in a QR. Frontend verifies offline with `@noble/ed25519` (audited, pure JS) rather than relying on WebCrypto Ed25519 support on every phone.
9. **Offline = provisional.** Offline scans never count as loaded until server sync accepts them; manifest close blocked until sync. Snapshot TTL is short (default 4h) and signed.
10. **Hold is an overlay, not a location state.** Keeps "where is the package physically" truthful while still blocking it.
11. **Location buckets derived only from scan + movement events** (never from a status flag).
12. **8D drafts from deterministic templates first.** Optional LLM narrative later; root cause is always `HYPOTHESIS`/`PENDING_HUMAN` until a human edits/approves.
13. **Numeric defaults (blur 80, glare 12%, SSIM 0.72, first-N 5, lookback 30 min, tightening 15%) are provisional** and live in `/policies`, calibrated on our fixture set and reported as such.
14. **No passport issuance during RED containment (v0.2).** Evidence is kept, but minting waits for distinct-unit recovery and QM clearance. A credential that exists before release stays a truthful record of what was certified. — Tradeoff: slower release after a 4M event.
15. **Frozen lot sampling with explicit inspection basis.** `SAMPLED_LOT` vs `INDIVIDUAL_100PCT` is signed into the passport, and A-parts are always individual. Without this the system would over-claim per-unit inspection.
16. **AQ1 envelope kept; payloads versioned to v2.** This avoids a JWS migration, and the scanner can reject claims it doesn't understand.
17. **Departure re-validates in one transaction with a global lock order** (heat → lot → unit → package → order → shipment), and physical follow-up is tracked as durable segregation tasks.
18. **Work split revised.** Claude/Opus owns UI plus all DB and transactional code. GPT/Astra owns seven isolated modules with typed interfaces. One writer per path removes the migration and lock-order conflicts two DB writers would create.
19. **Sync SQLAlchemy 2 + psycopg 3 behind FastAPI (threadpool), not async.** Explicit `SELECT … FOR UPDATE` transactions are simpler to reason about and test under real concurrency. — Tradeoff: per-request threads; fine at plant scale.
20. **Live mode adapts transport, not policy.** `frontend/src/api/live.ts` holds the only live-vs-mock differences: it reroutes `/units/:id` to `/detail`, nests the flat recall preview, flattens versioned policies, and tags fixture uploads as `SYNTHETIC_TEST`. Every decision still comes from the server. `/evidence/{sha}` alone also accepts `?access_token=`, because an `<img>` cannot send headers. — Tradeoff: the token can appear in local access logs; acceptable on the plant LAN, revisit with signed short-lived URLs.
21. **The demo is seeded through the public API, not SQL inserts.** `scripts/seed_demo.py` drives the same endpoints the UI uses, so seeded data carries real audit, outbox, signatures and evidence, and the story is a regression test (`tests/test_console_demo.py`). Browser fixture captures fetch the backend's own SYNTHETIC renders (`/demo/fixtures/*`), so they register against the calibrated golden reference.
22. **An 8D approval cites an uploaded review record, never a checkbox.** `POST /evidence` (QE/QM) stores the minutes as `UPLOAD` evidence, and the approval cites its SHA-256. Releasing a recall does **not** wait for physical tasks; open tasks stay visible until someone records what was done. — Tradeoff: a QM can release before the crate is physically moved, but the open task and its audit trail make that visible.
23. **E2E tests play the seeded demo story against the real stack.** Playwright's `live` project builds a fresh disposable database (see 26), then drives the UI through PostgreSQL-backed decisions in order. Specs pin their own serials, so earlier steps never disturb the dock packages later steps load. Only one `data-testid` was added (dock crates); everything else is found by role and visible text, so the tests also check the copy that explains *why*. — Tradeoff: serial, about 1.5 minutes.
24. **Real-time events are a hint to refetch, never data to trust.** The control room opens `/ws/events` with a single-use ticket from `POST /ws/tickets`, so the JWT never appears in a URL. Each committed outbox event refetches the screens on view. Bursts are debounced into one refetch, and each reconnect refetches everything, so a dropped socket costs only freshness, never correctness. Polling stays on as the fallback. Pop-ups (and the mutable siren) are reserved for alerts, physical tasks and revocations. Routine scans only update the views. — Tradeoff: one refetch per event burst rather than patching caches from payloads; simpler, and the payload can never disagree with the server.
25. **Offline loads must prove where they came from.** A provisional load is replayed as a load only if it cites a snapshot that was issued to the same device, operator and shipment, and that was valid at capture time (±2 min clock skew). Each event carries its own `snapshot_id`, because one batch can span shipments and refreshes. Otherwise it becomes a CONFLICT with a segregation task. An `ONLINE` event links to a recorded scan only if that scan has the same shipment+token fingerprint, device and operator. A resent sync repeats a conflict's unload instruction and task, so a lost response never loses it. — Tradeoff: an old phone queue without snapshot ids conflicts instead of loading; the client back-fills ids from stored snapshots when it can.
26. **Offline authorizations are settled per snapshot, explicitly; close and departure wait for them.** *(Supersedes the device-wide check-in of 45a6d3f.)* A snapshot authorizes one device and operator to capture offline for one shipment. It stays outstanding until settled:
    - **acknowledged** by the device ("End offline session"), which requires an empty queue at the server's chain head;
    - **superseded** by a refresh made with an empty queue. That settles only the device's *older* snapshots for the shipment, never the new one, which still authorizes captures;
    - **recovered** by a Quality Manager for a lost device, with an audited reason and an alert.

    Expiry settles nothing. A capture after settlement, or under a recovered snapshot, is a CONFLICT with a segregation task. Close and departure refuse while a snapshot is unsettled or an unload/segregate task for the shipment is open. That includes crates never on the manifest, such as offline loads refused after close. Issuance, settlement, recovery and close serialize on the shipment row; device rows are always locked before the business hierarchy. — Tradeoff: one more tap on the phone, and a lost phone needs a manager.
27. **E2E runs only against a disposable database.** Playwright starts its own API on a dedicated port (never reusing a running server). It sets `DATABASE_URL` itself, not from `.env`, to a local `*_e2e` database, which it recreates from scratch. With `AUTOQ_E2E=1`, the API refuses to boot and the demo reset refuses to run against anything else. — Tradeoff: about 20 s of setup per run.
28. **Replay is judged by the capture's own authority, not just today's gate.** A provisional load must also pass the snapshot's *signed* allowlist and held list, verified as of its issue time. The live gate alone could accept a crate the phone was never authorized to load. Those reasons enter the gate through an `authorize` hook, against the package the gate resolved from the verified token. An existing scan with the event's id that this capture did not produce is never adopted, on any path. Replays must cite the snapshot they cited first, and capture times must carry a timezone. AQ1 payloads and the six chain fields are unchanged; the per-event `snapshot_id` is a server-validated claim, not a chain field.
29. **Physical tasks never delete another scan's load.** `REMOVAL_REQUIRED` (recall, departure re-validation) unloads, but only a load on the shipment the task names. `SEGREGATION_REQUIRED` (a refused offline load) never unloads anything: that event created no load, so any load on the package belongs to a different, accepted scan. When the crate is recorded somewhere the task doesn't expect, a QE or QM must verify where it really is. The resolution is audited and the load is left as it is.
30. **Live events are at-least-once, socket authorization is re-checked, and missed critical events are recoverable.**
    - **Relay:** publishes first, then marks sent. A crash in between re-publishes (clients dedupe by `event_id`) instead of losing the push.
    - **Sockets:** each is re-checked every 15 s (`AUTOQ_WS_REAUTH_SECONDS`) and closed with 1008 when the account is deactivated, its roles change or the bearer session that minted the ticket expires (migration 0005). The client re-verifies the user and reconnects with a fresh ticket, or is signed out.
    - **Catch-up:** `GET /events?since=` serves committed HIGH/CRITICAL or siren events from the outbox itself, in the socket's envelope, for up to 24 h. The browser keeps a per-user cursor and the ids it has shown, asks from 2 minutes before the cursor to catch late commits, and marks those pop-ups "while disconnected", with one siren for a whole backlog.

    The WebSocket event contract is unchanged. — Tradeoff: re-checking is polling (a revoked user can receive up to 15 s more events), and the catch-up cursor lives in the browser, so a new device starts from "now".
31. **Offline load authority is judged at receipt; lost devices clear only through physical reconciliation.** *(Review of #33/#34.)*
    - **Settlement:** binds the device's terminal sequence **and** hash.
    - **Receipt:** a provisional event gains load authority only if the server *receives* it while its snapshot is unsettled, not under recovery, and unexpired. A claimed capture time can narrow authority, never extend it.
    - **Recovery:** first *requests* recovery, which ends offline authority and raises a `DEVICE_RECONCILIATION` task. The snapshot settles only with linked uploaded evidence or when a QE/QM completes that task.
    - **Locks:** every locked read refreshes the row (`populate_existing`), so checks made "under the lock" never judge a pre-lock copy. Every creator of a shipment-blocking task holds the shipment lock, which serializes it with departure (tested in both commit orders).
    - **Replay:** distinguishes a recorded null snapshot claim from pre-0006 rows whose claim is unknown, and compares the submitted `prev_hash`.

    — Tradeoff: honest phones that sync after expiry or settlement now need a physical check instead of loading automatically.
32. **Device-chain v2: readers first, then writers by policy, then the floor.** Astra's `chain_hash` (A4) reads v1 (six fields) and v2 (plus `chain_version` and the exact capture `snapshot_id`, null for ONLINE). The browser mirrors it and both are checked against the same interop vectors.
    - **Rollout:** two policy knobs (`offline.chain_writer_version`, `offline.chain_min_version`) roll the plant forward. The floor can never exceed the writer. Publishing a policy takes an advisory lock exclusively; each replayed event holds it shared while judging, so a floor change never splits a decision.
    - **Below-floor and regressions:** an event below the floor, or below what its device already wrote (an outdated tab), is still recorded so the chain and settlement can proceed, but it never confers load authority.
    - **Immutability:** history is enforced by the database. `device_events` is immutable, a snapshot's identity and expiry are immutable and its settlement is write-once, and a device checkpoint only advances, and only to a recorded event (checked at commit).
    - **Expiry:** taken from the signed snapshot payload, which must agree with the stored row.

    — Tradeoff: tests and repair scripts can no longer patch these rows. Corrections are new records.
33. **SPC containment is recommended by evidence and decided by people.** Astra's pure `investigate()` and `recommend_containment()` (#31, #35) receive what Opus reads through two ports: the committed inspection prefix, and a bounded genealogy of lots, units and the line's 4M changes. No exposure links are asserted, because none are recorded as independent evidence.
    - **Storage:** the investigation, the recommendation and what was read are stored verbatim with their versions. A trigger makes this evidence immutable and the decision final.
    - **Decision:** only a Quality Manager can approve, only lots the recommendation proposed, and only when it says REVIEW_RECOMMENDED. Each approved lot is then quarantined by its own recall, through the usual audited path.
    - **Honesty:** synthetic, uncalibrated and re-inspected data never qualifies, so the demo's drift honestly reads "insufficient evidence".

    — Tradeoff: unsampled same-line lots stay unresolved instead of being held "just in case".
